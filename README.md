# AI Investigation Engine — დოკუმენტების ანალიზისა და მოკვლევის სისტემა (Multi-Hop Hybrid RAG)

ეს პროექტი წარმოადგენს ხელოვნურ ინტელექტზე დაფუძნებულ მოკვლევის სისტემას (Investigation Engine), რომელიც ამუშავებს სხვადასხვა ფორმატის ტექნიკურ დოკუმენტაციას, სისტემური ცვლილებების ისტორიასა (Changelogs) და ინციდენტების ანგარიშებს (Post-mortems). უბრალო „Chat with PDF“ აპლიკაციისგან განსხვავებით, სისტემა რთულ კითხვებს შლის რამდენიმე ნაბიჯად, აკავშირებს სხვადასხვა წყაროში გაბნეულ ფაქტებს, პოულობს ურთიერთგამომრიცხავ ინფორმაციას და აბრუნებს დასაბუთებულ პასუხს ზუსტი ციტირებით.

## 1. სისტემის არქიტექტურა

1. **დოკუმენტების მიღება და დამუშავება (`app/ingestion.py`)**:
   - მხარდაჭერილია 4 ფაილის ფორმატი: `.pdf`, `.md`, `.txt` და `.json`.
   - დოკუმენტებიდან ამოდის ტექსტი და მეტამონაცემები (`doc_id`, `source`, `title`, `date`, `file_type`, გვერდის ნომერი).
   - **დუბლიკატების ფილტრაცია**: თითოეული ჩანქისთვის ითვლება ნორმალიზებული ტექსტის `MD5` ჰეში (`compute_content_hash`). თუ იდენტური შინაარსის ტექსტი უკვე დამუშავებულია, ბაზაში მეორედ აღარ ემატება.
   - **ორი Chunking სტრატეგია**:
     - `structure` (სტრუქტურული / აბზაცებზე დაფუძნებული დაჭრა — ნაგულისხმევი): ტექსტს ყოფს აბზაცებისა და სექციების მიხედვით ისე, რომ წინადადება შუაში არ გაწყდეს.
     - `fixed` (ფიქსირებული ფანჯარა): ტექსტს ჭრის 180-სიტყვიან ბლოკებად, 40-სიტყვიანი გადაფარვით (`overlap`).

2. **ვექტორული ბაზა, Hybrid Search და საკუთარი რანჟირების ალგორითმი (`app/search.py`)**:
   - **Semantic Search**: იყენებს `Qdrant`-ის ვექტორულ ბაზას და `BAAI/bge-small-en-v1.5` Embedding მოდელს (384-განზომილებიანი ვექტორები, `Cosine` მანძილი).
   - **Keyword Search**: იყენებს `BM25Okapi` ალგორითმს ზუსტი ტერმინების, კოდებისა და თარიღების მოსაძებნად.
   - **საკუთარი რანჟირების კომპონენტი (`custom_hybrid_ranker`)**: მზა ბიბლიოთეკაზე დაყრდნობის ნაცვლად, ხელით არის რეალიზებული ჰიბრიდული დალაგების ფორმულა, რომელიც აერთიანებს:
     - შეწონილ **Reciprocal Rank Fusion (RRF)** ქულას სემანტიკურ და BM25 რანგებს შორის;
     - ნორმალიზებული სემანტიკური და BM25 ქულების კომბინაციას;
     - საკვანძო სიტყვების გადაფარვის კოეფიციენტს (`coverage_score`), რიცხვითი/ვერსიის კოდების ზუსტი დამთხვევის ბონუსს (`+0.12`) და სათაურში დამთხვევის ბონუსს (`+0.10`).

3. **Multi-step RAG, Tool Calling და წინააღმდეგობების აღმოჩენა (`app/rag_agent.py`)**:
   - **Query Decomposition**: რთული, მრავალკომპონენტიანი კითხვა იშლება ქვე-კითხვებად (`decompose_query`).
   - **Tool Calling**: აგენტი სტრუქტურირებულად იძახებს ორ ხელსაწყოს: `search_knowledge_base` (ინფორმაციის მოძიება) და `verify_contradictions` (წყაროებს შორის წინააღმდეგობების შემოწმება).
   - **Abstention (პასუხისგან თავის შეკავება)**: თუ მოძიებული მტკიცებულებების ქულა ან შინაარსობრივი სიტყვების გადაფარვა ზღვარზე დაბალია, სისტემა არ იგონებს ფაქტებს და აბრუნებს დასაბუთებულ უარს.
   - **LLM ინტეგრაცია და Fallback**: იყენებს `Google Gemini 2.5 Flash`-ს, ხოლო ქსელური შეფერხების ან უფასო API ლიმიტის ამოწურვის შემთხვევაში ავტომატურად იყენებს სარეზერვო სინთეზატორს წყაროების (`[Source: doc_id]`) მითითებით.

## 2. ტექნიკური გადაწყვეტილებების დასაბუთება

- **რატომ Qdrant?** მუშაობს იდენტური Python API-ით როგორც ლოკალურ მუდმივ საცავზე (`data/qdrant_storage`), ისე Qdrant Cloud-ის უფასო ტარიფზე. აქვს სწრაფი მეტამონაცემებით ფილტრაცია დოკუმენტების წაშლისა და განახლებისთვის.
- **რატომ FastEmbed (`bge-small-en-v1.5`)?** მუშაობს ONNX Runtime-ზე მძიმე PyTorch/GPU გარემოს გარეშე, მოიხმარს მინიმალურ ოპერატიულ მეხსიერებას და იდეალურია უფასო ჰოსტინგის შეზღუდული რესურსებისთვის.
- **რატომ საკუთარი Hybrid Ranker?** მხოლოდ სემანტიკური ძიება ხშირად ვერ ასხვავებს კონკრეტულ ვერსიებსა და ინციდენტის კოდებს (მაგ. `v4.8.2`, `INC-309`, `CHG-884`). ჩვენი ალგორითმი ზუსტ კოდებსა და თარიღებს ანიჭებს დამატებით წონას, რამაც ტესტირებისას `Recall@5` გაზარდა `1.0`-მდე, ხოლო `MRR` — `0.9706`-მდე.

## 3. მონაცემთა ნაკრები (Dataset — 50,000+ ჩანაწერი)

სკრიპტი `scripts/load_dataset.py` ნაკადურად (streaming რეჟიმში) ამუშავებს **50,500 დამოუკიდებელ ტექსტურ ჩანაწერს** `hotpotqa/hotpot_qa` ბაზიდან და აერთიანებს მათ ტექნიკური ინციდენტების კორპუსთან (`danluu/post-mortems` სტილის ანგარიშებთან).
- 50,500-ვე ჩანაწერი გადის MD5 დუბლიკატების ფილტრაციას (სტატისტიკა ინახება `data/dataset_stats.json`-ში).
- უფასო CPU რესურსებზე სწრაფი და განმეორებადი შეფასებისთვის, ფიქსირებული `seed=42`-ით ირჩევა რეპროდუცირებადი ქვენაკრები, რომელიც ინდექსირდება Qdrant-ში.

## 4. გაშვების ინსტრუქცია

1. ბიბლიოთეკების დაყენება:
   `pip install -r requirements.txt fastembed`

2. (არასავალდებულო) გარემოს ცვლადების გაწერა:
   `export GEMINI_API_KEY="თქვენი_გასაღები"`

3. 50,000+ ჩანაწერის დამუშავება და ბაზის შევსება:
   `python3 scripts/load_dataset.py`

4. 42 სატესტო კითხვაზე ავტომატური შეფასების გაშვება:
   `python3 scripts/evaluate.py`

5. ავტომატიზებული ტესტების გაშვება:
   `python3 -m pytest -v`

6. სერვერისა და ვებ-ინტერფეისის ჩართვა:
   `uvicorn app.api:app --host 0.0.0.0 --port 8000`

## 5. Deployment-ის არქიტექტურა და უფასო ტარიფის შეზღუდვები

პროექტი კონტეინერიზებულია `Dockerfile`-ის საშუალებით და ეშვება ერთიან FastAPI სერვისად (რომელიც ემსახურება როგორც REST API-ს, ისე ვებ-ინტერფეისს). მონაცემები ინახება `data/qdrant_storage` საცავში (ან Qdrant Cloud-ზე), რაც უზრუნველყოფს ინდექსირებული დოკუმენტების შენარჩუნებას აპლიკაციის გადატვირთვის შემდეგ.
